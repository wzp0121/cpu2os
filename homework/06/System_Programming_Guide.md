# 系統程式設計指南：行程管理與檔案描述符重導向

本指南旨在深入淺出地解釋 Linux 作業系統中「行程管理」與「檔案描述符重導向」的核心概念，並提供一個 C 語言實作範例。

## 1. 檔案描述符 (File Descriptor, FD) 基礎

### 什麼是檔案描述符？

在 Linux/Unix 系統中，**檔案描述符 (File Descriptor, FD)** 是一個小型的非負整數，用來唯一識別一個由核心為行程開啟的檔案或 I/O 資源。這些資源不僅僅是磁碟上的普通檔案，還可以是管道 (pipes)、網路 Socket、終端機 (terminals) 等等。

當一個行程開啟一個檔案或建立一個 I/O 連線時，核心會返回一個 FD 給該行程，行程之後就可以透過這個 FD 來讀取、寫入或控制該資源。

### 核心預設的標準檔案描述符

每個新建立的行程，預設都會從核心繼承三個特殊的檔案描述符：

| FD 編號 | 名稱       | 說明                                                                                                                                                                                                                                                                     |
| :------ | :--------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **0**   | `stdin`    | **標準輸入 (Standard Input)**：通常指向鍵盤，行程從這裡接收輸入。                                                                                                                                                                                                       |
| **1**   | `stdout`   | **標準輸出 (Standard Output)**：通常指向螢幕 (終端機)，行程將正常的輸出內容寫入這裡。                                                                                                                                                                                    |
| **2**   | `stderr`   | **標準錯誤 (Standard Error)**：通常也指向螢幕 (終端機)，行程將錯誤訊息或診斷資訊寫入這裡。將錯誤輸出與標準輸出分離，可以讓使用者更容易地重導向正常輸出而不影響錯誤訊息的顯示。                                                                               |

這三個預設的 FD 是系統程式設計的基石，它們使得行程能夠與外部環境進行標準化的互動。

## 2. 行程建立與替換：`fork()` 與 `execvp()`

### `fork()`：複製行程

`fork()` 系統呼叫用於建立一個新的行程，稱為**子行程 (child process)**。這個子行程是呼叫 `fork()` 的行程，稱為**父行程 (parent process)** 的幾乎精確副本。

**底層行為：**

- 當 `fork()` 被呼叫時，核心會為子行程分配一個新的行程 ID (PID)。
- 子行程會繼承父行程的**程式碼段、資料段、堆疊、開放的檔案描述符**、環境變數、當前工作目錄等等。
- 儘管它們共享相同的程式碼，但它們各自有獨立的位址空間。在現代 Linux 核心中，`fork()` 通常採用**寫入時複製 (Copy-On-Write, COW)** 機制。這表示父子行程最初共享記憶體頁面，只有當任一方嘗試修改這些頁面時，核心才會複製一份新的頁面，確保各自的獨立性，從而提高效率。

**`fork()` 的雙重返回值：**

`fork()` 的行為比較特殊，它會返回兩次：

- **在父行程中**：`fork()` 返回子行程的 PID (一個大於 0 的整數)。
- **在子行程中**：`fork()` 返回 0。
- **發生錯誤時**：`fork()` 返回 -1，表示子行程建立失敗。

因此，我們通常透過判斷返回值來區分父子行程，並讓它們執行不同的程式碼邏輯：

```c
pid_t pid = fork();

if (pid == -1) {
    // 錯誤處理
    perror("fork failed");
    exit(EXIT_FAILURE);
} else if (pid == 0) {
    // 子行程邏輯
    printf("我是子行程，我的 PID 是 %d\n", getpid());
} else {
    // 父行程邏輯
    printf("我是父行程，我的 PID 是 %d，我的子行程 PID 是 %d\n", getpid(), pid);
    wait(NULL); // 父行程等待子行程結束
}
```

### `execvp()`：替換行程映像

`execvp()` 系統呼叫家族 (包括 `execl`, `execle`, `execlp`, `execv`, `execvpe` 等) 的作用是將當前行程的**程式映像 (program image)** 替換為一個全新的程式。這表示當 `execvp()` 成功執行後，原來的程式碼將不再執行，取而代之的是新載入的程式碼。

**底層行為：**

- 當 `execvp()` 被呼叫時，核心會載入指定的程式到當前行程的位址空間。
- **當前行程的程式碼、資料、堆疊會被新程式的內容覆蓋**。
- **行程 ID (PID) 不會改變**。這是一個關鍵點：`execvp()` 並沒有建立新行程，它只是替換了當前行程正在執行的程式。
- **開放的檔案描述符通常會被保留**。這就是 `dup2()` 能夠實現重導向的基礎，因為在 `execvp()` 之後，新的程式會繼續使用舊行程繼承下來的 FD。

`execvp()` 通常在 `fork()` 之後的子行程中呼叫，以執行一個外部指令：

```c
// 在子行程中
char *args[] = {"ls", "-la", NULL};
execvp("ls", args); // 執行 ls -la 指令
// 如果 execvp 成功，這行程式碼將不會被執行到
perror("execvp failed"); // 只有在 execvp 失敗時才會執行
exit(EXIT_FAILURE);
```

## 3. 檔案 I/O 操作

### `open()` 與 `close()`

- **`open(const char *pathname, int flags, mode_t mode)`**：
  - 用於開啟或建立一個檔案。
  - `pathname`：要開啟的檔案路徑。
  - `flags`：控制檔案開啟模式 (例如：`O_RDONLY` 只讀, `O_WRONLY` 只寫, `O_RDWR` 讀寫, `O_CREAT` 如果檔案不存在則建立, `O_TRUNC` 如果檔案存在則截斷為零長度)。這些旗標可以透過位元 OR `|` 組合使用。
  - `mode`：當 `O_CREAT` 旗標被設定時，指定新建立檔案的權限 (例如 `0644` 表示 r/w for owner, r for group and others)。
  - **返回值**：成功時返回一個非負的檔案描述符；失敗時返回 -1。

- **`close(int fd)`**：
  - 關閉一個已經開啟的檔案描述符。
  - `fd`：要關閉的檔案描述符。
  - **返回值**：成功時返回 0；失敗時返回 -1。
  - 每個開啟的 FD 都應該被 `close()`，以釋放系統資源。

### `read()` 與 `write()`

- **`read(int fd, void *buf, size_t count)`**：
  - 從指定的檔案描述符 `fd` 讀取 `count` 個位元組到緩衝區 `buf` 中。
  - **返回值**：成功時返回實際讀取的位元組數 (可能是 0，表示已到達檔案末尾)；失敗時返回 -1。

- **`write(int fd, const void *buf, size_t count)`**：
  - 將緩衝區 `buf` 中的 `count` 個位元組寫入到指定的檔案描述符 `fd` 中。
  - **返回值**：成功時返回實際寫入的位元組數；失敗時返回 -1。

## 4. 重導向的魔法：`dup2()`

`dup2(oldfd, newfd)` 系統呼叫是實現檔案描述符重導向的關鍵。它的作用是將 `oldfd` 所指向的檔案或 I/O 資源**複製**到 `newfd` 所指向的位置，並**原子性地關閉**原來 `newfd` 所指向的資源 (如果有的話)。

**工作原理圖解：**

假設我們有一個名為 `output.txt` 的檔案，其 FD 為 `file_fd` (假設為 3)。我們想要將 `ls -la` 的輸出從螢幕 (stdout, FD 1) 重導向到 `output.txt`。

```mermaid
graph LR
    subgraph Before dup2(file_fd, 1)
        A[程式行程] --> B(FD 0: stdin --> 鍵盤)
        A --> C(FD 1: stdout --> 螢幕)
        A --> D(FD 2: stderr --> 螢幕)
        A --> E(FD file_fd (例如 3): output.txt --> 磁碟檔案)
    end

    subgraph After dup2(file_fd, 1)
        F[程式行程] --> G(FD 0: stdin --> 鍵盤)
        F --> H(FD 1: stdout --> output.txt)
        F --> I(FD 2: stderr --> 螢幕)
        F --> J(FD file_fd (例如 3): output.txt --> 磁碟檔案)
    end
```

**詳細解釋：**

1.  **`oldfd` (來源描述符)**：你想要複製的檔案描述符。例如，你透過 `open()` 獲得的 `output.txt` 的 FD (假設是 3)。
2.  **`newfd` (目標描述符)**：你想要被覆蓋的檔案描述符。例如，標準輸出 `stdout` (FD 1)。

當你呼叫 `dup2(file_fd, 1)` 時：

-   如果 FD 1 已經開啟，它會首先被關閉。
-   然後，FD 1 會被指向與 `file_fd` (FD 3) 相同的檔案或 I/O 資源，也就是 `output.txt`。
-   從此以後，任何寫入到 FD 1 的內容 (原本是螢幕) 都會被寫入到 `output.txt` 中。

這就是 `ls > output.txt` 這種 Shell 重導向命令背後的機制。Shell 在執行 `ls` 之前，會先開啟 `output.txt`，然後在子行程中執行 `dup2()` 將子行程的標準輸出重導向到 `output.txt`，最後才 `execvp("ls", ...)` 執行 `ls` 指令。因為 `ls` 不知道它是在寫入螢幕還是檔案，它只知道寫入 FD 1，所以它會把輸出寫到重導向後的 `output.txt`。

**使用 `dup2()` 的步驟：**

1.  使用 `open()` 開啟目標檔案，獲取其檔案描述符 (例如 `fd_output`)。
2.  呼叫 `dup2(fd_output, STDOUT_FILENO)` (其中 `STDOUT_FILENO` 就是 1)，將標準輸出重導向到該檔案。
3.  **關閉原始的目標檔案描述符** (`fd_output`)。因為 `dup2` 已經複製了連結，現在 FD 1 已經指向 `output.txt`，所以 `fd_output` 這個描述符就不再需要，可以關閉以釋放資源。保留它會造成 FD 洩漏。
4.  執行 `execvp()`，新程式的輸出就會自動寫入到重導向後的檔案中。
