# 多執行緒與並行控制技術報告
使用opencode

## 一、 核心概念理論說明
* **Thread (執行緒)**：作業系統排程的最小單位，同一個行程（Process）內的執行緒會共享 Heap 記憶體，但各自獨立擁有 Stack。
* **Race Condition (競態條件)**：多個執行緒同時存取同一個共享資料，且結果取決於執行緒執行的相對順序，會導致資料不一致。
* **Mutex (互斥鎖)**：用來管理臨界區的同步機制，任何時刻最多只能有一個執行緒持有鎖，確保操作的原子性。
* **Deadlock (死結)**：多個執行緒互相等待對方釋放資源而陷入無限卡死。必要條件包括：互斥、持有並等待、不可剝奪、循環等待。

## 二、 實作機制總結對照表

| 實驗項目 | 面臨風險 | 採用的並行控制工具 / 策略 | 核心解決原理 |
| :--- | :--- | :--- | :--- |
| **1. 銀行存提款** | Race Condition (餘額錯亂) | `threading.Lock()` (Mutex) | 將非原子性的讀寫操作鎖定，強迫多執行緒互斥排隊執行。 |
| **2. 生產者消費者** | 緩衝區溢出 / 讀取空資料 | `queue.Queue` (內建條件變數) | 當緩衝區滿或空時自動阻塞（Wait）執行緒，供需平衡時再行通知（Notify）。 |
| **3. 哲學家用餐** | Deadlock (全體卡死) | 資源分級排序 (Resource Ordering) | 破壞 Coffman 死結四條件中的「循環等待」，使最後一個節點無法形成閉環。 |
