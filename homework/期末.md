## 二、作業 01：p0 編譯器實作 — 註解處理

### 1.1 簡介

p0 是一個精簡的教學用程式語言編譯器，本作業以版本 **08-comment** 為核心，在編譯器中加入單行（`//`）與多行（`/* ... */`）註解處理功能。編譯器以 C 語言實作，涵蓋詞法分析、遞迴下降語法解析、四元組中間碼生成以及堆疊框架虛擬機執行。

### 1.2 p0 語言 EBNF 語法

```ebnf
program       = { function_def | statement } ;
function_def  = "func" identifier "(" [ parameter_list ] ")" "{" { statement } "}" ;
parameter_list = identifier { "," identifier } ;

statement     = if_statement | assignment_statement | return_statement ;
if_statement  = "if" "(" expression ")" "{" { statement } "}" ;
assignment_statement = identifier "=" expression [ ";" ] ;
return_statement     = "return" expression [ ";" ] ;

expression    = arith_expr [ ( "==" | "<" | ">" ) arith_expr ] ;
arith_expr    = term { ( "+" | "-" ) term } ;
term          = factor { ( "*" | "/" ) factor } ;
factor        = number | identifier [ "(" [ argument_list ] ")" ] | "(" expression ")" ;

comment       = "//" { all_characters } newline | "/*" { all_characters } "*/" ;
```

### 1.3 編譯器三階段架構

#### 階段一：詞法分析（Lexer）

詞法分析器將原始碼轉換為 Token 串流，此版本加入註解過濾功能：

```c
void next_token() {
    while (1) {
        while (isspace(*src)) src++;
        if (*src == '\0') { cur_token.type = TK_EOF; return; }
        // == 註解處理核心 ==
        if (*src == '/' && *(src + 1) == '/') {           // 單行註解 //
            src += 2; while (*src != '\n' && *src != '\0') src++; continue;
        }
        if (*src == '/' && *(src + 1) == '*') {           // 多行註解 /* */
            src += 2; while (!(*src == '*' && *(src+1) == '/')) src++;
            src += 2; continue;
        }
        break;
    }
    // ... 數字、識別字、符號解析 ...
}
```

#### 階段二：語法解析與中間碼生成（Parser & Quadruples）

採用遞迴下降解析法（Recursive Descent Parsing），支援四則運算（含運算子優先級 `factor > term > arith_expr > expression`）、`if` 條件判斷、`while` 迴圈（搭配回填技術 Backpatching）、函數定義與呼叫。解析器在辨識語法結構的同時，直接生成**四元組（Quadruples）**形式的中間碼：

```
PC:  OP           ARG1        ARG2        RESULT
──────────────────────────────────────────────────
000: IMM         13          -           t1
001: PARAM       t1          -           -
002: CALL        check_prime 1           result1
003: JMP_F       cond        -           ?        ← 目標位址待回填
004: STORE       res         -           x
005: JUMP        -           -           000      ← 跳回迴圈開頭
```

- **條件跳轉**：`JMP_F` 在條件為假時跳轉，目標位址使用回填（Backpatching）技術
- **無條件跳轉**：`JUMP` 用於迴圈主體結束後跳回條件檢查處
- **函數呼叫**：透過 `PARAM` 將引數推入參數堆疊，`CALL` 時切換堆疊框架

#### 階段三：虛擬機執行（VM）

VM 以堆疊框架（Stack Frame）模型模擬函數呼叫的活動記錄（Active Record）：

| 元件 | 功能 |
|------|------|
| `Frame stack[1000]` | 每個 Frame 代表一個函數的執行環境 |
| `sp` (Stack Pointer) | 指向當前作用中的 Frame |
| `incoming_args[]` | 儲存從呼叫端傳入的參數值 |
| `ret_pc` / `ret_var` | 函數返回時恢復呼叫者的執行位置與結果變數 |

```
CALL 時的堆疊框架切換：
  呼叫前 (sp=0)         呼叫後 (sp=1)          返回後 (sp=0)
  ┌─────────────┐      ┌─────────────┐       ┌─────────────┐
  │ 全域變數     │      │ 全域變數     │       │ 全域變數     │
  │ ret_pc=???  │      │ ret_pc=PC+1 │       │ 結果已寫回  │
  │ ret_var=t1  │      │ ret_var=t1  │       │ ret_var=t1  │
  └─────────────┘      ├─────────────┤       └─────────────┘
  sp=0                  │ 函數局部變數 │       sp=0
                        │ incoming_args│
                        └─────────────┘
                        sp=1
```

本專案同時提供 **C、Python、JavaScript、Rust** 四種語言的相同功能實作，凸顯編譯器核心邏輯的語言無關性：

| C | `compiler.c` | 指標操作，效能最佳 |

### 1.5 p0 範例程式：質數判斷 (`prime_comment.p0`)

```p0
// p0 範例：判斷質數 (Prime Number)

// 手寫取餘數函數 (n % d)
func mod(n, d) {
    if (n < d) {
        return n;
    }
    return mod(n - d, d);
}

// 遞迴檢查是否能被整除
func is_prime_recursive(n, i) {
    if (i * i > n) {
        return 1;           // 沒找到因數，是質數
    }
    m = mod(n, i);
    if (m == 0) {
        return 0;           // 能被整除，不是質數
    }
    return is_prime_recursive(n, i + 1);  // 嘗試下一個除數
}

// 主進入點
func check_prime(n) {
    if (n < 2) { return 0; }
    if (n == 2) { return 1; }
    return is_prime_recursive(n, 2);
}

result1 = check_prime(13);   // 13 是質數，應為 1
result2 = check_prime(15);   // 15 不是質數，應為 0
```

此範例展示了 p0 語言的完整功能：遞迴函數呼叫、條件判斷、參數傳遞與回傳值。

### 1.6 關鍵技術

- **註解處理**：詞法分析階段過濾 `//` 與 `/* */`，不影響後續語法解析
- **運算子優先級**：遞迴下降 `expression → arith_expr → term → factor` 自然實現優先級
- **回填技術（Backpatching）**：`if`/`while` 的跳轉目標在產生完整指令序列後才填入正確位址
- **堆疊框架（Stack Frame）**：每個函數呼叫擁有獨立的變數空間，支援遞迴

## 三、作業 02：Nova 程式語言設計

### 2.1 簡介

Nova 是一套從零開始設計的程式語言，旨在以精簡的架構示範編譯器前端到後端的完整流程。語言採用**強靜態型態**、**縮排語法**（類似 Python），並編譯至自製的 **Nova Stack Machine（NSM）字節碼**執行。

### 2.2 語言特性

- **型態系統**：`int`、`float`、`bool`、`str`、`array[T]`、`struct`，無隱式轉型，所有型態轉換須明確使用 `as` 關鍵字
- **語法風格**：以縮排取代大括號，強制良好排版
- **記憶體管理**：引用計數（RC）策略，無 GC 暫停、無 Stop-the-World
- **目標架構**：堆疊機（Zero-address instruction），指令集精簡

### 2.3 編譯器架構（5 個 Stage）

```
原始碼 (.nv)
    │
    ▼ Stage 1: Lexer（詞法分析）
Token 流（含 INDENT/DEDENT）
    │
    ▼ Stage 2: Parser（語法分析，遞歸下降）
AST（Abstract Syntax Tree）
    │
    ▼ Stage 3: TypeChecker（型態檢查）
型態標註的 AST + 符號表
    │
    ▼ Stage 4: CodeGen（字節碼生成）
Nova Stack Machine 字節碼
    │
    ▼ Stage 5: NovaNSM（虛擬機執行）
程式輸出
```

### 2.4 程式範例

```nova
fn fib(n: int) -> int:
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

fn main() -> void:
    let i: int = 0
    while i < 10:
        print(fib(i))
        i = i + 1
```

### 2.5 Nova Stack Machine 指令集

NSM 為堆疊機架構，支援：

- 字面值：`PUSH_INT`、`PUSH_FLOAT`、`PUSH_STR`、`PUSH_BOOL`
- 變數操作：`LOAD_LOCAL`、`STORE_LOCAL`
- 算術與比較：`ADD`、`SUB`、`MUL`、`DIV`、`EQ`、`LT`、`GT` 等
- 流程控制：`JUMP`、`JUMP_IF_FALSE`、`CALL`、`RETURN`
- 陣列與結構體：`BUILD_ARRAY`、`ARRAY_GET`、`BUILD_STRUCT`、`GET_FIELD`
- 引用計數：`RC_INC`、`RC_DEC`

### 6.3 關鍵程式碼 — 哲學家用餐

```python
class Philosopher(threading.Thread):
    def __init__(self, id, left_chopstick, right_chopstick):
        if left_chopstick.id < right_chopstick.id:
            self.first_lock = left_chopstick.lock
            self.second_lock = right_chopstick.lock
        else:
            self.first_lock = right_chopstick.lock
            self.second_lock = left_chopstick.lock

    def run(self):
        with self.first_lock:
            with self.second_lock:
                # 成功取得兩把筷子，安全用餐
```

## 七、作業 06：行程管理與檔案描述符重導向

### 7.1 簡介

以 C 語言實作 `fork()`、`execvp()`、`dup2()` 三大系統呼叫，展示行程建立、程式替換與 I/O 重導向的底層機制。

### 7.2 核心程式流程 (`process_demo.c`)

```
父行程
  │
  ├─ 1. open("output.txt") 取得 FD
  │
  ├─ 2. fork()
  │      │
  │      ├─ 子行程：
  │      │    ├─ dup2(file_fd, STDOUT_FILENO)  // 重導向 stdout
  │      │    ├─ close(file_fd)                // 避免 FD 洩漏
  │      │    └─ execvp("ls", ["ls", "-la"])   // 執行指令，輸出寫入檔案
  │      │
  │      └─ 父行程：
  │           ├─ close(file_fd)
  │           ├─ waitpid() 等待子行程結束
  │           └─ open(output.txt) 讀取內容驗證重導向
```

### 7.3 技術重點

- **`fork()`**：採用 Copy-on-Write（CoW）機制，子行程繼承父行程的 FD Table、記憶體映射
- **`execvp()`**：替換行程映像而不改變 PID，保留已設定的 FD（含重導向後的 stdout）
- **`dup2(oldfd, newfd)`**：原子性地將 `newfd` 指向 `oldfd` 的資源，實現 Shell 風格的 `>` 輸出重導向
- **`waitpid()`**：父行程等待子行程結束，防止殭屍行程，並取得子行程的退出狀態

### 7.4 Shell 重導向的底層原理

```c
// 模擬 ls > output.txt 的核心步驟
int fd = open("output.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
pid_t pid = fork();
if (pid == 0) {
    dup2(fd, STDOUT_FILENO);  // stdout → output.txt
    close(fd);
    execvp("ls", args);       // ls 的輸出自動寫入檔案
}
waitpid(pid, NULL, 0);
```
